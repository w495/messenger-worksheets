# Команды чата

Команды отправляются отдельным сообщением в нужном треде.
`chat` означает обычный ответ, `task` — задачу с инструментами.
Квадратные скобки ниже обозначают необязательный аргумент.

## Синтаксис

| Команда | Действие |
|---|---|
| `/help` | Команды и настройки обоих маршрутов |
| `/task запрос` | Задача с инструментами и файлами |
| `/model` | Показать модель и уровень обоих маршрутов |
| `/model [chat\|task] модель [уровень]` | Выбрать модель треда |
| `/models [chat\|task]` | Каталог моделей обоих или одного маршрута |
| `/effort [chat\|task] [уровень]` | Показать настройки или изменить уровень размышлений |
| `/efforts [chat\|task]` | Уровни выбранной модели и их назначение |
| `/plan запрос` | План с доступом на чтение, без изменения файлов |
| `/review запрос` | Проверка кода с доступом на чтение, без исправлений |
| `/status` | Состояние запроса треда и прошедшее время |
| `/stop` | Отмена текущего запроса треда |
| `/reset` | Очистка контекста и копий файлов треда |

У `/help`, `/status`, `/stop` и `/reset` нет аргументов. Для `/plan`
и `/review` после команды требуется задание или источник.

Команды распознаются и с парным Markdown-выделением: `**/task**`,
`__/task__` или в обратных кавычках. Управление реализовано шлюзом;
поведение одноимённых команд интерактивной консоли Codex может отличаться.

HTTP(S)-ссылки и распознанные поручения вроде «создай» или «нарисуй»
тоже направляются в режим задач. Явный `/task` позволяет выбрать его
независимо от формулировки.

## Модель и уровень размышлений

`/model` без аргументов показывает текущие настройки обоих маршрутов.
`/model имя high` выбирает общие настройки треда и удаляет отдельные
переопределения `chat` и `task`. `/model task имя high` меняет только
задачи, `/model chat имя high` — обычные ответы.

Выбирайте точное имя из `/models`. Например:

```text
/models task
/model task ИМЯ_ИЗ_КАТАЛОГА high
/effort task xhigh
/efforts task
```

В примере замените `ИМЯ_ИЗ_КАТАЛОГА` на опубликованный идентификатор.
`/model default` удаляет все настройки модели треда. Вариант
`/model task default` удаляет только переопределение задач: после него
действует общая настройка треда либо worker.

`/effort high` сохраняет выбранные модели и меняет уровень обоих
маршрутов. `/effort task xhigh` меняет только задачи. Без аргументов
`/effort` показывает настройки. Изменения действуют на следующие
запросы; уже запущенная задача сохраняет прежние параметры.

Шлюз принимает названия `none`, `minimal`, `low`, `medium`, `high`,
`xhigh`, `max`, `ultra`. Их поддержку определяет выбранная модель
и провайдер. Значение `none` подходит текстовым моделям без отдельного
этапа размышлений, если провайдер поддерживает такой запрос.

`/efforts` показывает имя, текущий уровень и опубликованный набор
уровней модели последнего режима треда. Новый тред и `/reset`
выбирают для этой команды обычные ответы. `/efforts chat`
и `/efforts task` задают режим явно. Если источник не опубликовал
набор уровней, справка сообщает об этом.

Изменение модели не переключает авторизацию. Наличие имени в каталоге
не гарантирует доступ: провайдер проверяет его при вызове.

## Каталог моделей

`/models` читает Models API для API-маршрута и каталог Codex CLI
для задач. Списки могут различаться. Каталог кешируется на минуту,
официальный индекс карточек OpenAI — на час.

Модели выводятся карточками, до трёх на сообщение. Шапка содержит
режим, источник, страницу и выбранную модель. Новые модели идут
первыми; версии одной официальной карточки с одинаковыми свойствами
объединяются. Для API используются дата `created` или дата снимка,
для Codex — номер поколения и приоритет провайдера внутри поколения.

Карточки показывают назначение, опубликованные размеры контекста,
типы входа и уровни размышлений. Справка API дополняется официальными
карточками OpenAI, сведения Codex берутся из его каталога. Неизвестные
возможности отмечаются явно. Данные похожей модели не переносятся
на неподтверждённое имя. Характеристики модели не меняют инструменты
маршрута и [лимиты истории шлюза](configuration.md#история-и-файлы).

## Управление текущей задачей

Во время выполнения шлюз раз в секунду проверяет управляющие команды
того же треда. Обычные сообщения ждут в очереди. Справки `/models`
и `/efforts` загружаются в фоне, чтобы ожидание каталога не задерживало
`/stop`. Они показывают настройки на момент запроса и не меняют их.

`/stop` отменяет конкретный UUID задачи. Подтверждение приходит после
завершения её процессов. Другие задачи и worker продолжают работать.
Уже выполненные команды и внешние изменения не откатываются. Если связь
потеряна, шлюз сообщает, что остановка не подтверждена.

`/reset` доступен после завершения или подтверждённой остановки задачи.
Он удаляет локальную историю и сохранённые копии файлов, сохраняя
настройки модели. Старая история не загружается обратно из Мессенджера;
сами сообщения в чате остаются.

## Комментарии для участников чата

Перед отправкой модели из текста удаляются строки, начинающиеся
с `#` или `//` после пробелов или табуляции, и блоки `/* … */`.
Блоки могут занимать несколько строк и вкладываться друг в друга.

```text
# Пояснение для участников чата.
/task Создай check.txt с текстом OK.
// Эту строку модель не получит.
/* Ещё одно пояснение,
   которое останется только в чате. */
```

Модель получит только поручение создать файл. Комментарии не влияют
на выбор режима и не включаются в модельную историю.

Сообщение только из комментариев игнорируется целиком, даже если
у него есть вложение: статуса и реакций не будет. Вложения без подписи
обрабатываются. Символы в середине строки сохраняются, поэтому
`https://example.com/page#section` остаётся ссылкой. Незакрытый `/*`
скрывает остаток одного сообщения. Удалённый блок заменяется пробелом,
чтобы слова по его сторонам не склеились.

Фильтр применяется и внутри Markdown-блоков кода в сообщении.
Содержимое скачанных файлов и страниц он не меняет.
