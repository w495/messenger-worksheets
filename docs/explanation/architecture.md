# Маршруты, контекст и доставка

Messenger Worksheets состоит из шлюзов Мессенджера и обработчиков
модели, которые далее называются worker. Шлюз читает один чат,
хранит его состояние и доставляет ответы. Worker получает запрос
по HTTPS RPC, вызывает модель и возвращает текст и файлы.

## Почему два чата используют общий worker задач

API и Local различаются способом получения обычного ответа.
Для задач с инструментами у них один обработчик:

| Запрос | API-чат | Local-чат |
|---|---|---|
| Обычный текст | OpenAI Responses API с API key | Codex CLI |
| Задача с командами или файлами | Общий Codex worker | Общий Codex worker |
| HTTP(S)-ссылка | Общий Codex worker | Общий Codex worker |

API-маршрут отправляет обычный текст в Responses API без инструментов.
Поэтому `/task`, ссылка или распознанное поручение переключает его
на Codex worker. Названия чатов не означают отдельную авторизацию,
модель или изоляцию для задач.

Общий worker имеет сеть и инструменты Codex. Ссылку скачивает он,
содержимое страницы используется как данные задания. Инструкции
в загруженной странице не дают дополнительных полномочий.

Worker допускает до четырёх одновременных запросов. Каждый шлюз
последовательно обрабатывает сообщения своего чата, оставляя доступ
к [управляющим командам](../reference/commands.md) текущего треда.
Таким образом, лимит worker не означает четыре параллельных задания
в каждом чате.

## Контекст принадлежит треду

Корневой запрос создаёт отдельный тред. Продолжение получает
исходное задание, последние сообщения и копии созданных файлов.
История обычных ответов и задач общая: можно обсудить результат,
а затем попросить его изменить.

После файловой задачи продолжение остаётся в режиме инструментов.
В новом треде этот режим автоматически не включается. Он выбирается
по новому тексту или явной команде `/task`.

История хранится в SQLite и приватных копиях файлов шлюза.
Она ограничена по числу сообщений, объёму, файлам и числу тредов;
[точные пределы](../reference/configuration.md#история-и-файлы)
нужны для предсказуемого расхода памяти и диска. Большой контекст
модели не увеличивает эти пределы.

Команда `/reset` удаляет локальный контекст и ставит границу,
после которой старая переписка не загружается повторно из Мессенджера.
Публикации в самом чате при этом сохраняются.

## Доставка отделена от генерации

Сначала шлюз ставит 👀 на исходное сообщение и создаёт тред
с обновляемым индикатором. После успеха индикатор становится
`✅ Готово.`, реакция — ✅. Ошибка задачи или доставки приводит
к `❌ Ошибка.` и 💔.

Текст делится на сообщения по пределу Мессенджера — 4096 единиц
UTF-16. Emoji могут занимать две единицы. План частей, их UUID
и подтверждения сохраняются до отправки. После сбоя шлюз продолжает
доставку с недоставленной части, не вызывая модель заново.

PNG отправляется картинкой и отдельным документом. Мессенджер может
перекодировать картинку; документ позволяет скачать исходные байты.
Остальные файлы отправляются документами. После пяти неудачных
попыток доставка вложения прекращается. Копии, предназначенные для
доставки, удаляются после успеха или окончательного отказа; контекст
треда использует собственные ограниченные копии.

## Повторы и завершение задачи

UUID запроса определяется по чату и исходному сообщению. Повтор
с тем же UUID не запускает задачу второй раз. Worker сохраняет
хеш запроса и конечный результат, включая ошибку. Эти сведения
сохраняются и после удаления большого результата из кеша.

Ошибка worker завершает запрос и освобождает очередь. Если недоступна
доставка в Мессенджер, шлюз может повторить отправку сохранённого
ответа без нового вызова модели. Сохранение SQLite при обновлении
позволяет отличать эти случаи от нового задания.

Общий бюджет генерации — 30 минут. Повторное подключение Codex
использует оставшееся время, HTTP-модель ограничена временем дочернего
процесса. RPC ждёт до 31 минуты, чтобы получить результат или ошибку.
Отмена `/stop` относится к UUID одного запроса и подтверждается
после завершения его процессов.

Разделение аккаунтов и то, что означает слово sandbox в имени службы,
описано в [объяснении границ доступа](auth-and-permissions.md).
